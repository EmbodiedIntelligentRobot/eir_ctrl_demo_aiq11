# AMP 行走中的上半身离线动作

通过独立的 `/motion_cmd` 服务，在 **AMP HUMANOID WALK（28）** 中播放上半身动作。腿部继续由 AMP 控制，模式保持 28。标准配置默认不启用；使用 `config/pro_motion.yaml` 或包含 9500 感知策略的 `config/pro_perception_9500.yaml` 启用。

支持 PRO 的腰部、双臂、颈部位置轨迹和双手三指闭合度；手指规则见 [手指控制](手指控制.md)。当前 11–14 号资源实际控制腰部和双臂前四轴，颈部及未选中的关节保持原控制。MIMIC、感知行走和其他模式不接受动作播放。

## 启动与操作

先按 [应用说明](../README.md) 构建。`ehr_message` 必须包含 `MotionCmd.srv`；已有消息安装不含此类型时，按 [接口说明](../interfaces/README.md) 重新构建接口，再重编应用。

以下命令在工作空间根目录、已加载 ROS 和消息包环境的终端执行：

```bash
export AIQ11_PRO_MODEL="$PWD/sdk/share/eir_mujoco/aiq11_pro/model/urdf/aiq11_pro.xml"
/tmp/eir-ctrl-build/apps/eir_ctrl_demo_aiq11/eir_ctrl_demo_aiq11 \
  apps/eir_ctrl_demo_aiq11/config/pro_motion.yaml
```

另一终端进入 READY，查询到 `ready=true` 后进入 AMP：

```bash
ros2 service call /mode_switch ehr_message/srv/LocomotionModeSwitch '{cmd: 2}'
ros2 service call /mode_switch ehr_message/srv/LocomotionModeSwitch '{cmd: 0}'
ros2 service call /mode_switch ehr_message/srv/LocomotionModeSwitch '{cmd: 28}'
ros2 service call /motion_cmd ehr_message/srv/MotionCmd '{cmd: 11, session_id: "demo"}'
```

| cmd | 动作 |
| --- | --- |
| 11 | 奥特曼 |
| 12 | 欢呼 |
| 13 | 加油 |
| 14 | 再见 |
| 2 | 停止离线动作，平滑交回 AMP；空闲时重复调用有效 |

播放中可发送其他动作编号，或重复当前编号，从上次输出指令平滑重启。正常完成也会自动交回 AMP。服务 `result=true / err_code=0` 表示请求已应用，不代表动作已完成。

```bash
# 停止上半身动作，仍由 AMP 平衡
ros2 service call /motion_cmd ehr_message/srv/MotionCmd '{cmd: 2}'
# 查询模式及动作进度
ros2 service call /mode_switch ehr_message/srv/LocomotionModeSwitch '{cmd: 0}'
# 退出控制，切换到阻尼
ros2 service call /mode_switch ehr_message/srv/LocomotionModeSwitch '{cmd: 1}'
```

QUERY 返回 `upper_motion_cmd`、`upper_motion_phase`、`upper_motion_seconds`。阶段为 0 空闲、1 播放、2 等待 AMP 恢复、3 平滑交回；模式退出或故障取消动作。错误码为 1 不支持的命令、2 动作未加载、3 模式/期限/队列不允许。首版不实现 START、PAUSE、RESUME 或实时流输入；`session_id` 保留协议字段，仅作为调用方标签，不承担控制权仲裁。GUI 从 `motion_stream` 读取服务名和实际动作列表，并仅在 AMP WALK 中允许触发；也可直接使用服务调用。

## 配置和替换

入口配置仅新增一行：

```yaml
motion_stream: ../motions/pro/config.yaml
```

动作配置独立放在 `motions/pro/config.yaml`，包含编号与文件映射、机器人身份、服务名、过渡时间、恢复等待条件、最大推进时间步，以及各组观测参考姿态和目标角速度上限。

CSV 采用关节名映射，时间单位秒、位置单位弧度：

```csv
time,l_arm_1,l_arm_4
0,0.3,-0.89
0.02,0.31,-0.88
0.04,0.3,-0.89
```

时间必须从 0 开始严格递增，至少两帧；所有位置必须有限并在机器人配置范围内。列名不得重复；本体列必须属于配置中允许的腰、臂、颈关节，腿部列被拒绝。可选手指列使用独立的 12 槽映射与所有权掩码，值为 0–1 闭合度，保留槽不得写入。程序启动前加载并校验全部资源，运行中不热加载。每份 CSV 最多 100000 帧。

CSV 中出现的关节由离线动作接管，整段动作的所有权固定；其他关节保持 AMP 输出。接管任一组内关节时，AMP 当前帧中该组关节位置改用配置参考姿态，速度和上一动作置零；腿部观测与既有历史保留。停止后恢复真实观测，并要求收到本次恢复代号对应的两条新推理结果，避免把重复或在途旧结果当作恢复完成。

播放采用位置 PD，目标速度为零，增益沿用机器人 READY 配置；接管和交回时混合位置及增益，目标位置变化还受组内最大角速度限制。电机阻尼、并联映射、力矩限幅及其他保护保持生效。限速可能改变轨迹实际跟踪效果，替换动作需重新验收。

过渡和播放时间步最多按 `dt_cap` 推进，不补跑停顿期间的时间；反馈、策略结果和下发指令的实际年龄仍使用现有超时检查。超过 `recovery_warning_seconds`（默认 0.5 秒）后限频告警，保持接管关节目标并继续等待本次恢复代号对应的两条新鲜 AMP 结果，不再触发故障码 9。QUERY 的 `upper_motion_recovery_delayed` 表示等待延迟；底层反馈/推理/命令超时仍生效。切到 STILL 立即进入原阻尼路径，切到其他策略由现有模式过渡接管。

## 实现和资源来源

`src/motion.cpp` 是独立的纯 C++ 播放模块，复用现有 500 Hz 控制线程做有界插值与混合。CSV/YAML 在启动前读取；50 Hz 推理线程处理观测，非实时 IO 线程处理并联映射与下发，ROS 线程处理服务和诊断。不增加线程，不在控制线程执行文件 IO、推理、发布、互斥锁等待或堆分配。

四个 CSV 来自参考工程 `motion_stream/res/aiq11/offline/{11,12,13,14}`，分别为 `aoteman`、`huanhu`、`jiayou`、`zaijian`。按原始 44 关节布局与位置掩码提取已接管的腰、臂、颈轴，保留原时间和位置值，保留原有效手指列（29–33、35–39），移除保留槽及未使用字段；四份当前资源的手指值均为 0（张开）。没有迁移参考工程的规划管理器、IK/WBC 或可选重心优化实现。

## 验证

启用完整 PRO 模型测试后运行：

```bash
ctest --test-dir /tmp/eir-ctrl-build \
  -R '^(ctrl_test|ctrl_ros_motion_onnx|ctrl_ros_motion_libtorch)$' --output-on-failure
```

测试包含非法资源启动拒绝、腿部指令隔离、插值/限速、平滑重启、观测/历史隔离、恢复代号及独立推理计数、恢复延迟继续及后续交回、增益下发、模式退出和零堆分配。整机仿真分别播放四个完整动作，覆盖停止、重启及切到 MIMIC 后取消。

当前验证范围仅为软件与仿真；实机运动、动作质量、连续行走中的扰动、足底接触和长期负载仍需单独验收。工作空间测试结果及要求见 `doc/AIQ/上半身离线动作接入与测试.md` 和 `doc/AIQ/发布前测试需求.md`。
