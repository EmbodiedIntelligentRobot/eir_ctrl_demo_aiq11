# eir_ctrl_demo_aiq11 设计约定

## 范围

纯 C++ 应用，通过 eir_loco_runtime 控制机器人。保留 STILL（阻尼）、READY（准备姿态过渡及到位保持）、RL 三个状态；故障锁定不自动恢复。
当前支持 AIQ11 Pro 的 AMP HUMANOID WALK 和 MIMIC A–E。SPORT 的 STILL/READY/AMP WALK 已加入独立配置，待动态验收；其他 AMP/MIMIC 需要独立资源与验收。

## 三个独立选择

```yaml
robot: robots/pro.yaml               # Sport 后续增加独立配置
policies:
  28: ../policies/amp/pro/walk/config.yaml
  30: ../policies/mimic/pro/a/config.yaml # 31–34 对应 B–E
inference:
  backend: libtorch            # libtorch | onnx
```

机器人配置持有关节和电机名称/顺序、机构类型、标定文件、IMU 安装变换、READY 参数、非策略关节保持参数和保护限值。
策略配置持有支持的机器人身份、策略关节名称/顺序、观测项/历史、动作缩放、增益及模型路径。
推理配置持有后端、CPU 线程数和预热次数；当前明确使用 float32。构建可包含一个或两个后端，选择未编译的后端必须报错，不自动回退。

型号文件分别维护，不允许将 Pro 参数作为 Sport 的缺省值。启动时按名称生成固定索引表，检查重复/遗漏、机构对应关系、维度、参数范围和模型输入输出；运行中不进行字符串查找。
Pro 当前策略为 23 动作、每帧 78 维、10 帧、旧帧到新帧的 frame-major 输入；该契约属于当前模型，不是整个程序的全局维度。额外腕/颈关节必须有明确的保持和机构映射配置。

## 模块

- 程序入口：配置、资源准备、线程生命周期；操作入口兼容现有 ROS 2 遥控协议。
- 控制：状态机、READY 插值/到位检查、保护检查。
- 策略：reset/step 接口；AMP WALK 自己组装观测和维护历史，MIMIC 在独立文件中维护参考轨迹、姿态对齐与自己的观测历史。
- 推理：统一张量接口；LibTorch 与 ONNX Runtime 两个实现。
- 机器人映射：预计算关节索引、调用并联 SDK；不包含并联求解实现。

不迁移 ros2_control/hardware_interface、MPC/WBC、传统规划、复杂控制器管理器或插件系统。
AMP 上半身离线动作由独立的可选纯 C++ 播放模块实现，复用控制线程；腿部仍由 AMP 控制。仅接入必要的 MotionCmd 协议与位置轨迹，不迁移参考工程的 Motion Stream 规划框架。见 [上半身离线动作](上半身离线动作.md)。
参数文件启动时解析一次，不实现热更新。模型与配置不匹配时拒绝启动。

## 线程边界

| 执行上下文 | 工作 | 禁止/约束 |
| --- | --- | --- |
| 控制线程 | 状态机、有限维计算、保护、生成命令 | 不分配内存、不等待互斥锁、不访问文件、不推理、不打印、不发布 ROS |
| 推理线程 | 观测/历史、模型调用、策略结果 | 普通线程；不得直接发送电机命令 |
| SDK 数据交换 | runtime 读写及完整状态复制 | 隔离现有 SDK 分配/互斥锁；检查控制命令的生成时间，不能刷新过期命令 |
| ROS/主线程 | 遥控订阅、模式服务、日志、状态与可选 ROS 发布 | 低频普通线程，允许合并；不进入控制调用链 |
| runtime 已有线程 | 通信/仿真步进及独立看门狗 | 不重复实现 |

当前 runtime 的 read/write 不承诺实时安全，需要在控制线程外交换数据或提供经过验证的有界接口；不能仅设置 SCHED_FIFO 就宣称硬实时。
使用预分配、容量固定、生产者/消费者关系明确的数据通道。反馈、策略结果和命令均带单调时间及序号；策略结果还带状态会话编号。禁止旧会话结果跨状态切换应用，禁止无限沿用旧结果。
频率、CPU 亲和性、实时优先级和超时由配置指定，按机器与 SDK 线程约束校验。实时调度申请失败不能静默忽略。

## 私有并联 SDK

独立仓库放 internal/eir_closed_kinematics；公共头、动态库、查表/标定资源分别安装至 sdk/include、sdk/lib、sdk/share。
从已有 eir_closed_kinematics 仓库构建必要机构，不把实现复制到应用。保留独立版本来源与现有数值算法；剥离无关构建依赖。
机器人映射必须区分关节空间与电机空间，检查求解有效性/奇异性/边界。Pro 的额外机构也必须明确处理，不可假设全部是直接驱动。

## 可靠性与验收

1. 配置与型号不匹配、模型维度错误、非有限数值均在初始化或数据边界拒绝。
2. READY 在电机空间使用实测起点插值，并校验关节位置/速度到位、稳定时间和超时；进入 RL 需要显式请求；AMP/MIMIC 之间支持直接切换，并通过配置的短时目标插值衔接。STILL 初次启动仍要求 READY 到位。READY 只接受 STILL 来源，RL→READY 返回拒绝且不改变当前策略。
   有限角度越过配置范围只告警，STILL/READY/RL 均不中断；NaN/Inf 仍拒绝。告警数据通过固定容量通道送至非实时 ROS 线程，限频打印并支持 QUERY。
   位置控制只对目标做 IK；只有非零前馈力矩转换才校验并使用当前姿态的力矩映射，避免 READY 对下垂姿态执行不需要的逆解。
3. 推理过期/异常、反馈超时、机构求解失败进入明确的故障路径；看门狗不依赖推理和监控线程。
4. 保持 Pro 原策略观测、历史初始化、裁剪、动作缩放及混合输出语义；转换 ONNX 后以固定输入比较原模型及两种 C++ 后端。
5. 测试配置隔离、索引映射、历史顺序、状态切换、过期结果、异常输出、并联数值和仿真运行；诊断提供控制计算和推理耗时；尚未完成调度抖动/最坏执行时间验收。
6. Pro 先验收，Sport 单独验收。构建成功或最小仿真通过不能替代整机行走验收。

AIQ SDK 的持久急停修复已由工作空间交付。按用户确认的底层 SDK/真机验证条件，应用新增 PRO 独立硬件配置、反馈正解与编码器接入；本轮仅完成软件/仿真验证，见 [真机运行](AIQ11PRO真机运行.md)。

## 遥控与 ROS 2 边界

用户已指定使用现有遥控器，首版应用启用 ROS 2 输入适配层，核心控制和 runtime 不依赖 ROS。
复用现有 ehr_message 类型，避免修改类型名或删减协议定义导致通信不兼容；不引入旧控制器包。

| 接口 | 类型 | 应用职责 |
| --- | --- | --- |
| /loco_velocity_cmd | ehr_message/msg/LocoVelocity | 订阅 vx/vy/wz，检查有限值、范围和保持期限 |
| /mode_switch | ehr_message/srv/LocomotionModeSwitch | 服务端；实现 QUERY=0、STILL=1、READY=2、AMP=28、MIMIC A–E=30–34 |

名称和超时可配置。其他模式返回不支持，不能当作 STILL 或成功处理。RESET 在安全恢复语义完成前明确拒绝。
ROS 回调只做校验及有界请求交接，控制线程在周期边界应用。服务 result=true 必须表示切换已经实际应用，不能仅表示请求入队；返回实际 mode；故障时兼容原协议返回 STILL，并在 fb_msg 明确标记 FAULT 锁定。READY 进入成功不代表已经到位，只有到位检查通过后才能进入 RL。
请求带序号和期限，超过执行期限后不会执行。若 ROS 线程延迟响应，客户端应 QUERY 实际状态后再重试。STILL 独立优先通道，不排在普通切换请求后面；ROS 回调不能等待模型推理。
旧遥控发布端会在静止一段时间后停止速度话题，故速度超时只将目标速度归零，保留 RL 平衡。不能把缺少速度消息当作遥控硬件掉线；若需断连触发阻尼，必须接入真实连接状态/心跳。
遥控按键映射沿用现有发布端。应用不重复消费原始遥控话题并生成第二路切换指令。SDK 遥控若原本依赖 ehr_bridge 内部的发布器，需将该发布功能独立迁出，不能同时启动旧硬件 Bridge 占用设备。
当前 AMP 不支持的 gait_time、swing_height、keep_troting 等扩展不改变策略输入契约，需在适配文档中明确处理方式。

## 已确定的操作与诊断来源

remote.source=sbus 时，普通 ROS 线程读取 runtime 的 SDK SBUS 快照并解释配置中的轴和按键；remote.source=external 时，订阅已有 remote_stick 等节点发布的 LocoVelocity。模式切换服务始终提供。两种来源显式互斥，避免双路速度输入。
调试复用 prime_msgs 的 debug/runtime、debug/joint、debug/motor；开关、话题名和发布频率可配置。ROS 消息的构造、动态数组填充和发布均位于普通线程。
现有并联库含动态矩阵及打印路径，首版放在 SDK 数据交换线程；实时线程只做有界控制和保护计算。
