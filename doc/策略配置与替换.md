# 策略配置与替换

AMP 和 MIMIC 各自独立实现、独立配置、独立模型、独立状态；只共用推理后端、调度和安全检查。不使用插件加载、动态编译或配置热更新。

```text
src/policies/
├── amp.cpp                 # AMP 观测、历史、动作输出
└── mimic.cpp               # MIMIC 观测、轨迹、姿态对齐、动作输出
policies/
├── amp/pro/walk/
│   ├── config.yaml
│   ├── policy.pt
│   ├── policy.onnx
│   └── source.yaml         # 原始训练配置，仅追溯
└── mimic/{pro,sport}/{a,b,c,d,e}/
    ├── config.yaml
    ├── policy.pt
    ├── policy.onnx
    ├── motion.csv          # 参考动作，与模型成套替换
    └── source.yaml         # 原工程配置，仅追溯
```

SPORT WALK 已加入 `policies/amp/sport/walk/` 和 `config/sport.yaml`，不复用 PRO 的模型或机构拓扑。23 个关节、800 维输入与 100 Hz 相位观测的契约见 [SPORT 接入](SPORT接入.md)。SPORT 特殊 MIMIC 已加入独立的 `policies/mimic/sport/` 和 `config/sport_special_mimic.yaml`（50 Hz、544→23）；感知与上半身离线动作尚未迁移到 SPORT。

2026-10-13 的特殊 MIMIC 模型与参数更新见工作空间 [资源更新记录](../../../doc/AIQ/MIMIC资源更新记录.md)。SPORT 38 默认不用手，原姿态版本通过 `getup_prone_original/config.yaml` 选择。

2026-10-14 的 A–E 舞蹈更新见工作空间 [更新记录](../../../doc/AIQ/MIMIC_A至E资源更新.md)。PRO B 更新模型和轨迹，PRO A/C/D/E 相同二进制保留；两机型配置均采用包内值。SPORT A–E 使用 `config/sport_mimic.yaml` 独立仿真入口，544→23、50 Hz，不自动加入硬件入口。

## 选择策略和后端

PRO A–E 已按末端装配使用 `config_fist/gripper.yaml`、`policy_fist/gripper.pt/.onnx`、`motion_fist/gripper.csv` 和 `model_contract_fist/gripper.yaml`；上述目录树中的无后缀形式适用于 SPORT/其他策略。PRO 的 `config.yaml` 是指向 `config_fist.yaml` 的相对链接。入口可配置 `mimic_variant: fist|gripper|auto`，其中 auto 仅硬件使用，异常反馈默认 gripper。参数与模型契约必须同组；完整说明见 [装配选择](../../../doc/AIQ/PRO_MIMIC装配选择.md)。

策略可用 `contract: model_contract_gripper.yaml` 指定命名契约，路径相对策略配置；省略时仍从模型目录读取 `model_contract.yaml`。

运行配置 `config/pro.yaml` 将现有服务模式号映射到策略包；路径相对该运行配置。策略包内模型、动作路径相对包内 `config.yaml`。

```yaml
policies:
  28: ../policies/amp/pro/walk/config.yaml
  30: ../policies/mimic/pro/a/config.yaml
  31: ../policies/mimic/pro/b/config.yaml
  32: ../policies/mimic/pro/c/config.yaml
  33: ../policies/mimic/pro/d/config.yaml
  34: ../policies/mimic/pro/e/config.yaml
inference:
  backend: onnx            # 或 libtorch
  threads: 1
  warmup_steps: 10         # 模型启动预热，不是动作中的 warmup_steps
```

删除不需要的 MIMIC 映射即可不加载该动作，服务也会拒绝其模式号。AMP 保留用于速度输入配置。所有启用资源均在启动阶段加载并校验；缺失或不匹配时拒绝启动，不在运行中偷偷换模型。

## 模式切换

启动方式见 [应用 README](../README.md)。在另一个已加载 ROS 与消息包环境的终端执行：

```bash
ros2 service call /mode_switch ehr_message/srv/LocomotionModeSwitch '{cmd: 2}'
ros2 service call /mode_switch ehr_message/srv/LocomotionModeSwitch '{cmd: 0}'
# QUERY 确认 ready=true 后执行 MIMIC A
ros2 service call /mode_switch ehr_message/srv/LocomotionModeSwitch '{cmd: 30}'
# B/C/D/E 分别使用 31/32/33/34
```

从 STILL 首次启动仍需 READY 到位。AMP 与各 MIMIC 之间可直接请求 `28` 或 `30–34`，无需中间经过 READY；重复发送同一策略号会重启动作。
切换时从实测关节姿态过渡到新目标，`timing.policy_transition_seconds` 默认为 0.15 秒，设为 0 可禁用目标插值；只作用于策略间切换，不改变原来的 READY→AMP 行为。模型在普通推理线程运行，首条新结果到达前短时保持切换时的实测姿态；超过配置时限仍触发保护。插值不等于动态平衡保证。
READY 只允许从 STILL 进入；AMP/MIMIC 请求 READY 会被拒绝，当前策略继续运行。STILL 可随时请求，但地面阻尼不保证站立；不要把经 STILL 返回 READY 当作平衡恢复策略。

QUERY 的 `motion_frame=当前帧/总帧数` 使用从 0 开始的帧号；它表示参考进度，不保证机器人完全跟踪到位。

每次进入策略会重置本策略的观测历史、上一动作、首帧停留和轨迹进度；旧会话输出不被使用。MIMIC 不消费速度话题，USB/SBUS 的模式服务语义相同；SBUS 快捷键可在运行 YAML 中配置 30–34。

## 当前 PRO 模型契约

| 项目 | AMP WALK | MIMIC A–E |
| --- | --- | --- |
| 实现 kind | `amp_humanoid_walk` | `mimic_gravity_v1` |
| 输入 | 78 × 10 = 780 | 166 × 4 = 664 |
| 输出 | 23 个关节 | 29 个关节，另有 3 个颈部轨迹关节 |
| 历史 | 按帧，旧→新 | 按观测组，各组旧→新 |
| 周期 | 20 ms | 20 ms |
| 初始化 | 重复首帧 | 重复首帧；前 5 次观测 last_action 为零 |
| 完成行为 | 持续行走/平衡 | `loop: false`，继续推理跟踪末帧，不自动切换 |

MIMIC 观测组固定为：参考关节位置+速度、相对姿态前两列（按行展开）、实际基座重力、参考基座重力、实际躯干重力、参考躯干重力、角速度、关节位置偏差、关节速度、上次动作。
躯干旋转顺序为 `R_base × Rz(yaw) × Rx(roll) × Ry(pitch)`；入场使用参考工程的相对 yaw 对齐。角速度为机身坐标，四元数为世界坐标下基座姿态，wxyz。

`motion.csv` 无表头，每行 **68 列**：`quat_wxyz[4], q[32], dq[32]`。前 29 个 q/dq 对应策略的 `joints`，后 3 个对应 `mimic.tracked_joints`。速度起点在第 37 列，不能按 29 维动作误读偏移。
A 不额外停留首帧；B–E 停留 2 秒，期间参考关节速度为零。非循环结束后保留文件末帧的位置和速度语义。

各动作的关节 Kp/Kd、额外电机阻尼和动作缩放均在本动作配置内；不覆盖 AMP 参数。颈部位置/速度随文件播放，`tracked_kp/kd` 沿用当前 runtime 已验证的颈部保持增益（20/2），未采用旧工程公共颈部增益（45/0.75）。并联颈部速度通过 SDK 转到电机空间。

## 替换一个动作

1. 复制目标动作目录为新版本目录，保留模型、原始配置和轨迹的成套来源。
2. 更新该目录的 `policy.pt`、`policy.onnx`、`motion.csv` 和 `config.yaml`；校对机器人身份、关节顺序、增益、动作缩放、历史维度及周期。
3. 只修改运行 YAML 中对应模式号的路径；重启生效。保留旧目录可快速回滚。
4. 比较两后端相同输入的输出，再验证 READY、动作全程、末帧保持、READY 拒绝且保持当前策略、AMP 回归。不能仅凭模型加载成功验收。

若新模型观测含义、顺序或网络输入不同，必须新增/调整对应家族的实现与契约测试，不能只把 `history` 改到维度相符。不在 AMP 中添加 MIMIC 分支。

PT 要求 TorchScript、单个 float32 `[1,664]` 输入、单个 `[1,29]` 输出。当前 A–E 和新增 PRO 六个特殊动作均符合维度契约；特殊动作有独立朝向/入口/阻尼配置。元组输出和 Flow MIMIC 不在当前范围。

在目标策略包目录导出 ONNX（需 PyTorch、onnx；覆盖已有文件）：

```bash
python3 - <<'PY'
import torch
import onnx
model = torch.jit.load('policy.pt', map_location='cpu').eval()
torch.onnx.export(model, torch.zeros(1, 664), 'policy.onnx',
    input_names=['observation'], output_names=['action'],
    opset_version=17, dynamo=False)
onnx.checker.check_model('policy.onnx', full_check=True)
PY
```

`.pt/.onnx` 使用 Git LFS；提交前检查 `git lfs status`。轨迹、配置与源码正常纳入 Git。

## 感知行走

PRO 感知行走独立放在 `src/policies/perception.cpp` 和 `policies/perception/pro/walk/`，运行入口 `config/pro_perception.yaml`，模式号 41。模型与 manifest/config 成套替换，启动校验 SHA256 和输入输出契约；不共用 AMP/MIMIC 历史。详细说明见工作空间 `doc/AIQ/感知行走迁移与测试.md`。

## 感知模型整合与拆分

运行配置 `inference.perception_execution` 选择 `combined`（默认）或 `split`，AMP/MIMIC 不受此选项影响。整合资源由 profile 的 `models` 配置；拆分 encoder/actor 由同目录 `manifest.json` 的 `split_models` 按后端配置文件名与 SHA-256。当前契约为 encoder `[1,8,18,32] → [1,128]`，actor `[1,752] → [1,23]`，无 hidden 状态。替换资源需同时核验输入顺序、动作缩放、相机处理版本及两种输出等价；修改完毕执行真实模型加载和仿真回归。默认 CNN/actor 均 50 Hz，不能把历史采样 10 Hz 误认为网络更新频率。线程与实机验收见顶层 `doc/AIQ/感知推理方案与性能验收.md`。

## PRO 特殊动作（实验配置）

`config/pro_special_mimic.yaml` 单独启用模式 35/36（仰面/俯卧躺下）、37/38（对应起身）、42/43（下蹲/起立）；普通配置不加载它们。资源分别在 `policies/mimic/pro/{liedown_supine,liedown_prone,getup_supine,getup_prone,stand_to_squat,squat_to_stand}/`。

当前 PRO、SPORT 六个特殊动作成套使用 `10_13_完整全部动作.zip` 的模型、轨迹和参数；本项目配置格式转换不改变原值。用户确认包内参数已仿真验证，本轮软件测试通过，仍需本项目落地闭环与实机验收。旧版闭环结论仅保存在工作空间历史记录中。

STILL 必须先 READY；37 仅来自已完成的 35，38 仅来自已完成的 36，按配置校验初姿和角速度。42 可立即切 AMP 或 43，43 仅来自 42，不再要求 42 到末帧。旧会话目标被拒绝，沿用已有位置过渡。

替换须成套更新 `config.yaml`、原始 `source.yaml`、PT/ONNX、轨迹及 `model_contract.yaml`。`output_mode` 保留源配置值；`HYBRID_PRO` 的踝 Kd 在执行层只施加一次，不改写配置数值。机型、观测/动作顺序、缩放、模式、输出类型和哈希必须一致。完整参数映射、来源与验证边界见 [资源更新记录](../../../doc/AIQ/MIMIC资源更新记录.md)。
