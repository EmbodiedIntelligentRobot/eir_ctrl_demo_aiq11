# PRO 三指手控制

双手三指各占 6 个 SDK 槽：5 个主动关节，第 6 槽保留为零。手指闭合度统一为 **0 张开、1 闭合**；IO 线程转换为 SDK 的 0–100%，不进入 RL 观测或网络动作。

| 左手槽 | 右手槽 | 关节 |
| --- | --- | --- |
| 0 | 6 | `fg1_1` 主指 |
| 1 | 7 | `fg2_0` 副指旋转 |
| 2 | 8 | `fg2_1` 副指弯曲 |
| 3 | 9 | `fg3_0` 副指旋转 |
| 4 | 10 | `fg3_1` 副指弯曲 |
| 5 | 11 | 保留，不控制 |

机器人配置 `config/robots/pro.yaml` 的 `hand_control` 设置开关、三阶段目标与时长、闭合度变化速度上限、最大推进步长和仿真 Kp/Kd。关闭 `enabled` 恢复旧的仿真固定张开保持。`simulation_hand` 继续配置映射、四连杆标定和左右手力矩上限，当前为 1.39 Nm。

READY 开始从实测位置执行“张开 → 主指闭合 → 副指闭合”，随后保持。AMP、MIMIC 与感知行走共用该日常姿态；策略互切不会重复启动开合。STILL 停止推进并冻结最近目标；FAULT 不继续发送动作，保留原 SDK 急停机制。再次从 STILL 进入 READY 时从实测手指位置重新执行序列。

在 `config/pro_motion.yaml` 中，`/motion_cmd` 的 11–14 动作额外接管手指。当前四份原始轨迹的有效手指值均为零，即播放期间张开。正常完成或 STOP 后，从最后目标重新执行日常序列；切离 AMP 也释放接管。只有 CSV 中指定的手指被接管，其余保持最近目标。

替换动作时直接增加手指关节名列，无需改代码：

```csv
time,l_arm_1,l_fg1_1,r_fg1_1
0,0.3,0,0
0.5,0.3,1,1
1,0.3,0,0
```

本体关节仍使用弧度，手指使用闭合度。时间严格递增、从零开始，位置必须有限并在范围内；错误资源在启动前拒绝。保留槽不能出现在 CSV。所有目标变化受 `max_velocity` 限制，配置过慢会延长日常阶段或影响轨迹跟踪。

不新增线程：启动线程读文件，现有控制线程做有界计算，IO 线程调用 SDK。手指反馈缺失/离线、非法目标进入锁定 FAULT 10；原反馈/命令看门狗及 SDK 拒绝保护同样适用于手指。

启用 `debug.enabled` 后，`debug.hand_topic`（默认 `debug/hand`）发布 `prime_msgs/msg/DebugJointArray`：`joint_num=12`，`q_act/q_des` 为闭合度，`tau_act` 为 SDK 力矩；本轮只填这三个数组，其余数组留空。遥控/调试发布均由 ROS 线程完成。

```bash
ros2 topic echo /debug/hand prime_msgs/msg/DebugJointArray --qos-reliability best_effort
```

软件及双推理后端仿真已验证，详细结果见工作空间 [三指控制接入与测试](../../../doc/AIQ/三指控制接入与测试.md)。GUI 动作质量和实机尚未验收；本应用硬件运动入口仍禁用。SDK 单电机 EIRGRIPPER 不属于此功能。
